# 1. Engineering Log

A chronological ledger of multi-session debugging efforts that resulted in significant architectural pivots, and notable manual implementations worth recording for future context. New entries go at the top. Keep entries terse — one paragraph, no rehashed code.

- **2026-05-24 — FXAA (Phase 7 Slice 3).** Single fullscreen post-process anti-aliasing pass running after the tonemap, on the sRGB display-space image. Compact NVIDIA-derived "FXAA Console" variant (~40 lines of frag, no macros) — samples center + 4 diagonals, fast-paths flat regions via a luma-range threshold band (absolute floor + relative-to-max), otherwise computes an edge direction from diagonal luma gradients and walks 1–8 texels along it for a two-tier sample blend, falling back to the narrower blend if the wider one overshoots. `Renderer3D::FXAAPass(source_tex, w, h)` exposed; `ViewportPanel` gained a third RGBA8 `mFinalFramebuffer` so the chain becomes HDR scene → tonemap → LDR intermediate → FXAA → final display. ImGui::Image now shows the final FXAA buffer; entity picking still reads from the HDR framebuffer's RED_INTEGER attachment (unchanged). The pre-FXAA LDR intermediate is required because GL doesn't allow reading from and writing to the same texture in a single pass. Defaults: edge threshold floor 0.0312, relative threshold 0.125 — both well-validated values from the FXAA 3.11 reference. Most visible improvement: bright PBR highlights and contrasty geometric silhouettes no longer show pixel-stairstep aliasing.

- **2026-05-24 — Bloom polish: 2D linearization + Karis prefilter (Phase 7 Slice 2 follow-up).** Two issues surfaced testing Slice 2. **(1) Bloom firefly flicker** — single sub-pixel HDR brights (IBL sun region, sharp specular) flickered as the editor camera sub-pixel position shifted between frames, popping the bright tap in/out of the downsample sum with huge magnitude swings. Fix: Karis 2013 weighted average in the prefilter step of `bloom_downsample.frag`. Groups the 13 taps into 5 overlapping quads with Jimenez weights (center 0.5 + four outer 0.125), and Karis-weights each quad's 4 samples by `1/(1+luminance)` before averaging — compresses firefly magnitudes pre-average so the difference between "tap included" and "tap excluded" is small. Non-prefilter downsample passes keep the plain partial average since their input is already smoothed. **(2) 2D content rendered pale** — Renderer2D shaders wrote sRGB-authored values directly into the RGBA16F HDR buffer, then the unified tonemap pass treated them as linear and applied ACES + gamma, double-encoding to a washed-out look. Fix: added `pow(oColor.rgb, vec3(2.2))` linearize step to `quad.frag`, `circle.frag`, `line.frag`, and `grid.frag` so 2D output conforms to the same "linear into HDR FB" contract that `mesh.frag` and `skybox.frag` use. Properly fixes the brightness mismatch that Slice 1 deliberately deferred — 2D scenes now look identical to pre-HDR-pipeline, with the bonus that mixed 2D + 3D scenes share one consistent display curve.

- **2026-05-24 — Bloom (Phase 7 Slice 2).** Modern dual-filter bloom (Jimenez 2014 / COD: Advanced Warfare) layered onto the unified HDR pipeline. `Renderer3D::BloomPass` runs a chain of up to 6 mip-down framebuffers (each RGBA16F, half the previous), each downsample sampling 13 taps with Jimenez's weighting; the first iteration folds in a hard-threshold bright-pass so only HDR pixels above the threshold spread. Upsample walks the chain back to mip 0 with a 3x3 tent filter under additive blending (`GL_ONE, GL_ONE`), so each level accumulates a wider, softer contribution from all smaller levels. The final texture (scene/2 resolution) is sampled and additively composited inside `tonemap.frag` before ACES, so the bloom benefits from the tonemap's HDR roll-off naturally. `Renderer3D` owns the entire chain — shaders, framebuffers, and three runtime knobs (`SetBloomEnabled/Threshold/Intensity`) — lazy-resizing the mip chain when scene resolution changes. Caller surface is one extra line in `ViewportPanel::EndFrame` between the scene-FBO unbind and the tonemap call. **State save/restore** covers blend enabled+func, depth test, FBO binding, and viewport so the pass can't leak state into subsequent draws (the BRDF LUT pattern from B.3). **Shader uniform API gained** `UploadUniformFloat2` for passing `uSrcTexelSize` per mip level. Defaults: threshold 1.0 (HDR only), intensity 0.04 — subtle out of the box; scene-level knobs land in a follow-up slice with Scene Properties UI + serialization.

- **2026-05-24 — Unified HDR pipeline (Phase 7 Slice 1).** Moved the per-shader ACES tonemap + sRGB encode out of `mesh.frag` and into a dedicated fullscreen post-process pass. `ViewportPanel` now owns two framebuffers: the existing scene framebuffer upgraded from RGBA8 to RGBA16F (so linear radiance values > 1.0 survive until the tonemap pass) and a new LDR RGBA8 display framebuffer. `EndFrame()` runs a `tonemap.vert` / `tonemap.frag` fullscreen-triangle pass (no VBO — `gl_VertexID` trick, empty VAO) that samples the HDR Color 0 attachment, applies ACES, and writes sRGB-encoded LDR into the display buffer. ImGui::Image now shows the LDR buffer; entity picking still reads from the HDR buffer's RED_INTEGER attachment (Color 1) — no picking logic changed. `FramebufferTextureFormat::RGBA16F` added to the engine abstraction with a matching `GL_RGBA16F` / `GL_FLOAT` path in `OpenGLFramebuffer::Invalidate`. **`mesh.frag` changes:** removed `ACESFilm` function and the final `tonemapped = ACESFilm(lit)` + gamma-encode block; PBR output is now raw linear HDR. Debug viz modes 1 (irradiance) and 6 (prefilter) that previously inlined their own ACES now output linear samples — the unified tonemap pass applies roll-off correctly to HDR env data. Mode 5 (albedo) outputs the already-linearized albedo directly. All modes pass through the tonemap pass, which is slightly more correct than the old per-mode inline approach. **2D / grid note:** Renderer2D and the editor grid still write display-space (sRGB) values into the HDR float buffer; ACES at values ≤ 1 is close to identity (slight contrast boost), so 2D content looks approximately the same. Full 2D linearization is the next Phase 7 follow-up. **Key win:** emissive materials with factor > 1 now properly bloom/roll-off via ACES instead of hard-clamping to 1.0 in RGBA8. Mixed 2D+3D scenes no longer have independently-tonemapped layers.

- **2026-05-24 — Normal mapping (Phase 5 material textures, final slice).** Completes the PBR material texture set. `MeshVertex` gained a `glm::vec4 Tangent` field (xyz = world-space tangent, w = handedness sign); `MeshAsset::Create` reads `cgltf_attribute_type_tangent` when present and falls back to Lengyel per-triangle accumulation when absent (projects edges onto the UV plane, accumulates into `tan_sum`/`btn_sum` per vertex, Gram-Schmidt re-orthogonalizes, derives sign from `dot(cross(N,T), B)`). `MeshMaterial` gained `NormalTexture` (URI same relative-path / embedded-skip semantics as `ORMTexture`). VBO layout extended to `Float4 a_Tangent` at attribute location 3. **Shader side**: `mesh.vert` reads `aTangent.xyz`, Gram-Schmidt re-orthogonalizes T against N (corrects interpolation drift at sharp creases), derives B = `cross(N,T) * w`, and outputs `vWorldTangent` / `vWorldBitangent`; `mesh.frag` re-normalizes T/B/Ng after interpolation, builds `mat3 TBN = (T, B, Ng)`, decodes `texture(uNormalMapTexture, vTexCoord).rgb * 2 - 1`, and transforms to world space — the result replaces `vWorldNormal` as the per-fragment N for all PBR math. **Fallback**: `FlatNormalTexture` is a 1×1 RGBA=(128,128,255,255) pixel stored as `0xFFFF8080` on little-endian; decodes to tangent-space `(0,0,1)` which TBN maps back to the geometry normal — existing meshes without a normal map are fully unaffected (no `uHasNormalMap` branch). Unit 10 is the new slot (`uNormalMapTexture`). **Full wiring**: `MeshRendererComponent.NormalTexturePath` / `.NormalTexture`, lazy-load in `DrawMeshEntity`, `Renderer3D::Submit` signature (normal texture added before `transform`), serializer read/write in both deserialization paths, inspector drag-drop + browse + clear slot after the Emissive row, "Import Material from glTF" button now also pulls `normalTexture`.

The set now dogfoods every shipped engine system end-to-end: 2D sprites / sprite animation / tilemap + per-tile collision / Box2D physics / audio, prefabs, glTF mesh loading, PBR + IBL, CSM shadows, Jolt 3D physics, scene transitions, and particles — the validation gate before Phase 6. - **2026-05-21 — Editor: Duplicate Entity (Ctrl+D, undoable) + sandbox `physics_playground` scene.** The duplicate feature surfaced as a gap while building the 3D-physics demo scene (9 dynamic Box/Sphere/Capsule props — building each from scratch was untenable). New `Scene::DuplicateEntity(Entity)` deep-copies an entity — every component plus its child subtree — into the same scene with fresh UUIDs, parented as a sibling of the source; a variadic `CopyEntityComponents` fold mirrors `Scene::Copy`'s component list, and the components' copy constructors null runtime handles (physics bodies, sounds) so the clone carries no aliased state. Editor side: `EntityDuplicateCommand` (first Execute clones + snapshots the copy to prefab YAML, redo restores that exact copy by UUID, undo destroys it — the same snapshot pattern as `EntityDeleteCommand`), a Scene Hierarchy context-menu item, and a Ctrl+D shortcut gated to edit mode + non-text-input. The `physics_playground` scene itself validated Jolt 3D physics end-to-end (all three collider types, 3D collision events via `collision_logger.lua`); one authoring note worth recording — `CapsuleCollider3D` is fixed to the local Y axis, so capsule meshes must be modelled upright (Blender +Z, which the glTF exporter maps to engine +Y) or the mesh and collider won't align.

- **2026-05-21 — Sandbox `platformer_2d` demo scene + three systemic bug fixes surfaced by dogfooding it.** First scene of the rewritten sandbox plan (`SANDBOX_SCENES.md`) — a 2D platformer that exercises the whole 2D stack: tilemap floor + painted platforms with per-tile collision, a cat sprite-sheet character (idle/run/jump clips), sensor-pickup coins built from a `.lprefab`, score HUD, audio. Two Lua scripts written: `player.lua` (A/D move, rising-edge velocity jump gated by a downward ground-ray, velocity-driven 3-frame jump pose, facing flip) and `collectible.lua` (`OnSensorBegin` → bump the `Score` text via `GetText`/`SetText`, trigger a tag-resolved `SFXPlayer`, self-`Destroy`). **Three bugs found while building it, all systemic:** (1) **Sensors never fired** — Box2D 3.1 only reports a sensor↔visitor overlap if the *visitor* shape also sets `enableSensorEvents`; `scene.cpp` set it on sensor shapes only, so a non-sensor player collider was invisible to coin sensors. Fixed by enabling it on every 2D shape. (2) **Crash after a pickup** — `Scene::DestroyEntity` removed the entt entity but left its Box2D body alive; the orphaned body kept emitting events and catching raycasts, and the player's ground-ray then resolved a hit to the dead entity → `GetComponent` fatal. Fixed by tearing down the runtime body (Rigidbody2D + Tilemap) inside `DestroyEntity`, plus a hardened `resolve_shape` in the contact/sensor dispatch that validates shape→body→entity at each hop and skips events touching a dead handle (defends against a body destroyed mid-dispatch-batch). (3) **Crash on Stop after selecting then collecting an entity** — the editor held the hierarchy selection as a raw handle into the runtime scene; destroying that entity mid-Play left `OnSceneStop` calling `GetComponent<IDComponent>` on a dead handle (`operator bool` is a null-check, not a liveness check). Added `Entity::IsValid()` (registry-validated) and made `SceneManager` always remap-or-clear the selection across every play/stop scene swap so a handle can never outlive its scene. **3D follow-up flagged:** `DestroyEntity` still doesn't tear down Jolt bodies — same orphan bug will hit the 3D scenes' runtime `Destroy()` calls; to be fixed when `physics_playground` / `character_controller` are built.

- **2026-05-21 — glTF material import (Slice 1) + two systemic textured-mesh bug fixes.** `MeshAsset` now extracts the first primitive's `pbrMetallicRoughness` block (baseColorFactor, metallic/roughnessFactor, base-color texture URI — percent-decoded via `cgltf_decode_uri`) into a `MeshMaterial`, exposed via `GetMaterial()`; embedded `.glb` textures are detected and skipped with a warning since Slice 1 resolves only external-file URIs. (2) Mesh albedo textures loaded with the default `TextureSpecification` (Filter=Nearest — correct for pixel-art sprites, blocky on 3D meshes); added a shared `kMeshAlbedoTextureSpec` (Linear + mips) routed through all six mesh-albedo load sites (the AssetManager cache is spec-keyed, so all sites must agree or duplicate textures load). Slice 2 (metalRoughness texture), normal/AO/emissive maps, and embedded-`.glb`-texture decode remain Phase 5 follow-ups.

- **2026-05-20 — PBR IBL Slice B.3 (specular split-sum + BRDF LUT) + runtime log file sink.** Final IBL slice — brings the env-driven specular term that B.2 deliberately deferred, completing the metallic-roughness PBR story. Karis 2013 split-sum approximation = roughness-convolved prefilter cubemap × an environment-independent BRDF LUT, sampled per fragment and combined with a Lazarov roughness-aware Fresnel on the IBL path only. Standard Schlick saturates `F` to 1.0 at grazing regardless of roughness (physically right for mirrors, too bright for rough surfaces that scatter most of the grazing reflection), so the IBL path uses `F = F0 + (max(1-r, F0) - F0) * (1 - NdotV)^5`; direct lighting keeps plain Schlick. New `TextureCubemap::CreatePrefiltered(env, face_size=256)` walks the 9-mip chain with `roughness = mip / (mips-1)`; each mip is GGX-importance-sampled (1024 Hammersley samples) and drawn into the existing per-face FBO via the B.1/B.2 `RenderToCubemapFaces` helper. Reuses B.2's Karis 2014 mipmap pre-filter trick (LOD = 0.5·log2(saSample/saTexel)) to suppress firefly aliasing on bright HDR pinpoints — without it, mid-roughness mips show single-bright-texel artifacts. The BRDF LUT is engine-global, generated once at `Renderer3D::Init` via a fullscreen-triangle pass (gl_VertexID, no VBO; empty VAO satisfies core-profile bind requirement); 512² RG16F, Hammersley + GGX importance sampling, Smith-G with the IBL k = a²/2 remap (different from mesh.frag's direct-lighting k = (r+1)²/8 — both are valid Smith variants). Owned as raw GL state in `Renderer3DStorage` because Texture2D is RGBA8-only and adding a format-enum for a single-instance global wasn't worth it. **Bug bundled in:** initial LUT-pass helper leaked `GL_BLEND` (and color mask + clear color) into long-lived render state — diagnosed by "PBR works but grid + camera icon went opaque after boot." Expanded the GL-state save/restore set to cover everything the helper touches. **Diagnostic hardening added at the same time:** framebuffer-completeness check + `glGetTextureSubImage` center-pixel readback with a loud `LOOM_CORE_ERROR` if the LUT is still all-zero post-draw — turns a silent black-IBL bug into a one-line diagnosis. Texture units finalize at 0=albedo, 1-4=shadow cascades, 5=irradiance, 6=prefilter, 7=BRDF LUT. Scene-side: lazy `GetPrefilterCubemap` mirroring B.2's irradiance, propagated through `Scene::Copy`, reset on `SetSkyboxPath`; `OnUpdateEditor` gains a `fallback_prefilter` param so the editor's default-HDR prefilter layers on top when the scene has no env (same pattern as B.2's irradiance fallback). Two new debug-viz modes (6 = prefilter sample at the surface's actual roughness; 7 = BRDF LUT lookup as `(R=scale, G=bias)`) exposed in the toolbar DEBUG VIZ dropdown. **Bundled separately:** spdlog gains a `basic_file_sink` so every `LOOM_/LOOM_CORE_` macro now tees to `logs/loom.log` (CWD-relative, lands at `build/<config>/bin/logs/loom.log`). Truncated each Init for "one session per file" diagnostics, `flush_on(warn)` so warnings + errors hit disk even if the next frame crashes, try/catch on construction keeps engine init alive on a non-writable CWD.

- **2026-05-19 (later) — Scene-owned environment + editor fallback split + Scene Properties panel migration + env face_size 1024 → 2048.** Architectural follow-up to B.2 turning the skybox/IBL pair from an implicit `Scene` member into a properly-modeled scene property with explicit edit-vs-play semantics. Previously the env lived on Scene but the viewport drew the skybox ad-hoc; play mode and edit mode were indistinguishable and there was no way to ship a level with deliberately no environment. **Three concrete changes:** (1) `Scene` owns the env as a scene property — `mSkyboxPath` persists via `SceneSerializer`, derived cubemaps cache lazily, empty path means the scene has no env assigned (no implicit fallback). (2) `EditorLayer::LoadFallbackEnvironment` loads `resources/environments/default.hdr` once at boot into a new `EditorEnvironment { Equirect, Skybox, Irradiance }` (B.3 adds `Prefilter` to this); `ViewportPanel` hands the fallback to `OnUpdateEditor` + `DrawSkybox` only when the scene has no env of its own, so PBR surfaces are never pitch-black during level construction. (3) Play mode's `OnUpdateRuntime` renders the skybox itself using only the scene's own cubemap — with no env assigned, the framebuffer clear shows through and PBR ambient goes to zero (which is what the shipped game will show, by design). `Renderer3D::DrawSkybox` extracted from the inline viewport draw so both paths share one impl, owning the cube VAO + skybox shader. **Crucial bug fix landed inside this slice:** `Scene::Copy` didn't propagate `mSkyboxPath` or the prebuilt cubemap pointers, so hitting Play silently dropped the skybox even with a scene env assigned (the runtime scene started with empty env). Added 5-line propagation to the end of `Copy`; also shares the cubemap pointers across scenes so the ~200 MB env + irradiance pair doesn't rebuild on every play start. **Bundled separately:** env cubemap face_size bumped 1024 → 2048 — editor camera uses ~30° FOV, so at 1024² the cubemap's angular density was ~2× lower than the viewport's, producing a visible bilinear upscale ("looks like 480p"). 2048² brings cubemap density to ~22.8 px/deg vs the viewport's ~22 px/deg at typical sizes; doesn't add detail beyond the source HDR's resolution ceiling, just removes the upsample-blur step. **Bundled separately:** UI moved out of the toolbar Settings popup (wrong category — skybox path describes the scene, not editor view-state) into a new Unreal-style `ScenePropertiesPanel` (dockable, View → Scene Properties toggle). Toolbar's former "SCENE — SKYBOX" section renamed to "DEBUG VIZ" — Skybox Source combo + Mesh Debug Viz stay there since they're editor/renderer debug, not scene data. `mesh.frag` lost its constant `kFallbackAmbient = vec3(0.03)`; ambient is now strictly the IBL diffuse term (or zero when no irradiance is bound), matching the design intent — the editor's fallback IBL provides the lit baseline, and play mode honors the scene's exact config.

- **2026-05-19 — PBR IBL Slice B.2 (diffuse irradiance), with a cube-conversion bug fix carried over to B.1.** Diffuse irradiance cubemap convolved from the B.1 env cubemap, driving the ambient diffuse term in `mesh.frag`. Brute-force hemisphere convolution (integer-counted loops, 256×96 = 24,576 samples per output texel) plus **Karis 2014's mipmap pre-filtering**: each integration sample reads a source-cubemap mip whose texel solid angle matches the sample's, so bright HDR pinpoints get pre-averaged into many texels instead of being aliased into per-output-texel variance. Pure Karis match (LOD = 0.5·log2(saSample/saTexel)) wasn't enough for studio HDRs with concentrated bright lights — sphere showed faint concentric "moiré rings" from leftover variance — fixed with a **+2 LOD bias** on top of the formula. Diffuse is low-freq enough by definition that the extra blur removes no real directional content. **Crucial bug fix that affected both B.1 and B.2**: `RenderToCubemapFaces` was drawing all 36 cube vertices per face view (`glDrawArrays(TRIANGLES, 0, 36)`), so the 4 lateral non-target faces' triangles also projected into each view's framebuffer (cube corners sit inside the 90° frustum). With no depth attachment on the FBO and front-face culling alone, the last-drawn face overwrote the intended face's edges → "hard split" regions on a sphere wrapping the irradiance cubemap, and subtle corner-blur on the env cubemap. Fix: `glDrawArrays(TRIANGLES, 6*face, 6)` — render only the 6 vertices of the face being targeted, no overlap possible, no depth test needed. `Renderer3D` gains `SetIrradianceMap` (bound at texture unit 5) and `SetDebugViz` (uniform pipeline for PBR/irradiance/normal/NdotL/NdotV/albedo isolation modes, driven by a toolbar dropdown — invaluable for the hour spent isolating "is this the cubemap or the framebuffer?"). `Scene` gains lazy `GetIrradianceCubemap` (rebuilds with the skybox dirty flag) and a `SkyboxSource` debug toggle that lets the viewport render the irradiance cubemap directly as the skybox. Other infrastructure that landed in this slice: env cubemap allocates a full mip chain (bilinear-averaged via `glGenerateTextureMipmap` — B.3 prefilter will overwrite with roughness-convolved variants), `glEnable(GL_TEXTURE_CUBE_MAP_SEAMLESS)` at engine init (was never enabled, contributing to face-boundary seams on low-res irradiance), anisotropic filtering on all cubemaps, HDR `Texture2D` loads forced to `FilterMode::Linear` regardless of the spec default (default was `Nearest` for pixel-art, which point-sampled HDR equirect textures during cube conversion). `mesh.frag` IBL diffuse path uses `textureLod(uIrradianceMap, N, 0.0)` — explicit mip 0 — because the irradiance map is low-freq by construction and trilinear minification produced visible mip-transition rings on curved surfaces ("LOD lottery"). Trade-offs deliberately deferred: importance-sampled convolution (overkill for diffuse, will use the pattern for specular B.3), HDR framebuffer + final tonemap pass (would let us drop the per-shader ACES, but the current per-shader tonemap is fine until 2D + 3D need consistency), 8-bit dither (NdotV debug confirmed the framebuffer doesn't band at this contrast range).

- **2026-05-18 — Gizmo re-migrated from custom to ImGuizmo.** Reversed the 2026-05-09 ImGuizmo removal. The 2026-05-09 retrospective blamed NFD's focus-stealing for ImGuizmo's "handles latching / phantom click" symptoms — that theory turned out to be wrong. Real root cause, finally found during this re-migration: **`ImGuizmo::BeginFrame()` creates an internal full-screen `NoInputs` ImGui window named `"gizmo"` and pins its drawlist into `gContext.mDrawList`. `IsHoveringWindow()` then does `FindWindowByName(mDrawList->_OwnerName)` and compares against `ImGui::HoveredWindow`. A `NoInputs` window can never be the hovered window, so the check always fails → `mbMouseOver = false` → `GetMoveType()` early-exits `MT_NONE` → `IsOver()` always returns false → no hover highlight, no drag, even though the gizmo draws correctly.** The fix is `ImGuizmo::SetAlternativeWindow(ImGui::GetCurrentWindow())` called from inside the viewport's `Begin`/`End` scope — ImGuizmo's `IsHoveringWindow` has a second escape hatch (`gContext.mAlternativeWindow`) specifically for the "docked editor where the gizmo's drawlist owner isn't the real interactive surface" case. One line of code. **Side benefit**: the swap deleted ~600 LOC of custom screen-space gizmo math (GizmoHandle enum, axis/plane/ring picking, drag-state machine, screen-projection helpers, ApplyDeltaToLocal) replaced by ~50 LOC of ImGuizmo wiring (SetRect + Manipulate + decompose result via existing `Math::DecomposeTransform`). Undo batching preserved via `IsUsing()` edge detection — snapshot the local transform on false→true, push a single `TransformEditCommand` on true→false. Wiring details that mattered: (1) `ImGuizmo::BeginFrame()` must run at the top of `OnImGuiRender`, before any `Begin/End` (initially placed inside the dockspace `Begin`, which left ImGuizmo's "current window" tracking confused); (2) ImGuizmo and ImGui are separate static libs in the weaver binary — weaver's `GImGui` must be plugged into ImGuizmo via `SetImGuiContext()` right after `EditorLayer`'s `SetCurrentContext()`; (3) `<imgui_internal.h>` required in `viewport_panel.cpp` to access `ImGuiWindow*` and `GetCurrentWindow()` for `SetAlternativeWindow`. ImGuizmo linked into the `weaver` target only (not the engine), preserving the 2026-05-09 audit's "no DLL boundary" mitigation. Validation: drag-translate / rotate / scale all work; world/local toggle (X) flips; one drag = one undo step (not per-frame); parent-child rotations restore correctly through `inverse(parent_world)`; click on non-handle viewport area still selects the entity under cursor.

- **2026-05-18 — F-to-focus actually works now: ImGuiLayer keyboard gate relaxed.** Polish v2 thought it had fixed "F doesn't fire after clicking a hierarchy entity" by relaxing the gate inside `EditorLayer::HandleShortcuts` to be editor-global. It didn't — the event never reached HandleShortcuts in the first place. **Root cause**: `ImGuiConfigFlags_NavEnableKeyboard` is on, so clicking a TreeNode in the hierarchy sets `io.WantCaptureKeyboard = true`. `ImGuiLayer::OnEvent` was blocking events when `mBlockEvents && WantCaptureKeyboard`, so the F KeyPressedEvent got `Handled = true` and `Application::OnEvent`'s break-on-handled stopped propagation before EditorLayer's turn. **Fix**: switched the keyboard-block predicate from `WantCaptureKeyboard` to `WantTextInput` — only block when an actual text widget needs the keys, not when keyboard nav has merely focused a non-text widget. Matches Unity/Unreal: editor shortcuts always reach the editor unless you're typing into a textbox. Mouse-block predicate (`WantCaptureMouse`) is unchanged; it's correctly tight already. Validation: click an entity in the hierarchy and immediately press F (mouse anywhere outside text fields) — camera reframes. Click into the entity's tag input field and type "f" → still adds an "f" to the name (text-input gate intact).

- **2026-05-18 — Editor camera polish v2: F is now editor-global + Blender-ish grid defaults.** Two issues found right after the Blender-style camera landed. **(1) F-to-focus didn't fire after clicking an entity in the Scene Hierarchy.** The first cut gated F on `ViewportFocused`; clicking a hierarchy row transferred focus to that panel, so F was silently swallowed. Tried relaxing to `ViewportFocused || ViewportHovered`, but the mouse is *over the hierarchy panel* at that moment too, so hover was also false. - **2026-05-18 — PBR direct lighting, Slice A (Cook-Torrance, no IBL).** Replaced the Blinn-Phong evaluation in `mesh.frag` with the standard metallic-roughness microfacet BRDF — `MeshRendererComponent.Roughness` and `Metallic` sliders are now physically meaningful (they were plumbed-but-ignored since Phase 4). **BRDF**: GGX normal distribution `D` (Trowbridge-Reitz with perceptual→linear roughness via `a = roughness²`), Smith geometry `G` with Schlick-GGX (direct-lighting `k = (r+1)²/8` remap), Schlick Fresnel `F`. **F0** = `mix(vec3(0.04), albedo, metallic)` — dielectrics share ~4% reflectance, metals tint by albedo (the whole point of the metallic flow). **Per-light evaluation** (`EvaluatePBRLight`): `specular = D·F·G / (4·N·V·N·L + ε)`; `kS = F`; `kD = (1-kS)·(1-metallic)`; final = `(kD·albedo/π + specular) · radiance · N·L`. Same function handles directional and point lights — they only differ in how `radiance` is computed. - **2026-05-18 — Shadow mapping, Slice D (cascaded shadow maps).** Slice C polish gave us crisp shadows up to 30 world units; everything beyond that fell into the "fully lit" fallback. - **2026-05-18 — Shadow mapping, Slice C polish v2 (texel-snap fixed).** First polish pass shipped a texel snap that was a no-op: `center_ls = unsnapped_view * center` always returns `(0, 0, -radius)` because `center` is the look-at target by construction. - **2026-05-18 — Shadow mapping, Slice C polish (sphere-bound + texel snap + distance clamp).** Initial Slice C fit an **AABB** of the full camera frustum to the shadow ortho. - **2026-05-17 — Shadow mapping, Slice B (PCF + slope-scale bias).** Two wins on top of Slice A's hard shadows. **Tried + reverted: front-face culling during the depth pass.** Intuition said it'd kill self-shadow acne by recording the caster's back face into the shadow map. In practice it created an irreparable "shadow gap" at every contact point — back-face depth ≈ ground depth at the caster's base, so any positive bias pushed the contact pixel out of shadow, and zero bias produced flicker. Reverted to default culling (no cull tweak) so the shadow map records the caster's front face — contact points naturally have different depths and shadow cleanly. Bias-only is fine for acne when paired with PCF. **PCF (Percentage-Closer Filtering)**: `mesh.frag::SampleShadow` now does a 3×3 kernel — texel offsets derived from `1.0 / textureSize(uShadowMap, 0)` so the kernel scales correctly if the shadow map resolution changes — and averages 9 single-sample depth comparisons into a `[0..1]` visibility scalar. Hard binary lit/shadowed boundary becomes a single-pixel soft gradient; the wavy silhouette stairstep is gone. Cost is 9 texture fetches per fragment per draw call instead of 1, which is fine for our 3D scene volumes; widening to 5×5 (25 fetches) is reserved for a future "soft shadows" toggle. **Slope-scale bias** replaces the constant `kShadowBias = 0.0015`: `bias = max(0.005 * (1 - dot(N, L)), 0.0005)`. Surfaces nearly parallel to the light direction (grazing N·L close to 0) get the widest tolerance — where depth-precision wobble would otherwise drop self-shadow acne — while perpendicular surfaces (N·L ≈ 1) get the 0.0005 floor so the shadow doesn't lift off the geometry (peter-panning). N is the surface normal; L is the first directional light's vector (the only shadow-casting light in Slice A/B), computed once at the top of `main()` and threaded into `SampleShadow(vec4, vec3, vec3)`. **Bonus fix bundled with this slice:** inspector field carryover bug — editing an `InputText` for entity A and then clicking entity B in the hierarchy committed the staged buffer into entity B's value, because the inspector never namespaced its widget IDs by entity. Validation: the same scene from Slice A — directional light, mesh on ground — silhouette is now a smooth soft edge instead of a 1-pixel stair, no acne pattern visible on shallow-lit surfaces, no visible gap between shadow and caster contact point. Drag-start snapshots the local transform + parent world; drag-end pushes the command only if any component changed beyond `1e-5f`. `EditorContext` gained `GizmoOp` (None/Translate/Rotate/Scale) and `GizmoMode` (World/Local). Shortcuts: W/E/R/Q switch operation, X toggles space — gated on `ViewportFocused && !WantTextInput`. Toolbar gained functional T/R/S/- buttons and a Local/World toggle (visual styling deferred to UX pass). `EditorLayer::OnMouseButtonPressed` now calls `mViewportPanel.BeginGizmoDragIfHovered()` before falling back to entity selection so the gizmo claims clicks first.

- **2026-05-14 — CPU particle system added.** New `ParticleComponent` (engine/include/loom/scene/components.h) carries emitter config (Point/Box/Circle shape, world-vs-local sim space, spawn rate, lifetime/velocity/gravity ranges, color/size over normalized lifetime, max-particle cap, optional texture) plus a per-emitter `Live` pool and `SpawnAccumulator` of runtime state (not serialized). All sim + render logic lives as inline static helpers in `scene.cpp` (`TickParticles`, `DrawParticles`, `UpdateAndDrawParticleEntity`) wired into both `OnUpdateEditor` and `OnUpdateRuntime` — particles tick in the editor too so the Game Developer gets a live FX preview without entering Play. Rendering reuses the existing `Renderer2D::DrawQuad` matrix overloads (one quad per particle, batched by the existing renderer); no new entry point. World-space mode keeps particles flat at the emitter's Z and ignores emitter rotation/scale; local-space mode multiplies by the full emitter world matrix so particles inherit movement. `Live` is cleared on `OnRuntimeStart` and `OnRuntimeStop` so editor preview state never leaks across mode transitions. Inspector UI is left to a follow-up commit per division of labor.

- **2026-05-13 — Manually implemented a custom Font Manager for the editor UI.** Pulled all font loading out of `ImGuiLayer::OnAttach` and into a dedicated `Loom::FontManager` singleton (`engine/include/loom/asset/font_manager.h` + `engine/src/asset/font_manager.cpp`). `FontType` enum covers the editor's typography slots: `Small`, `Medium`, `MediumBold`, `Large`, `LargeBold`, and `Monospace`. Public static API: `Init(dpi_scale)` builds the atlas (called once during ImGui setup), `Get(FontType)` returns the `ImFont*`, and `Push`/`Pop` wrap `ImGui::PushFont`/`PopFont` for scoped overrides. Each UI font merges Inter (Latin) with Noto Sans Thai (`resources/fonts/inter/`, `resources/fonts/noto_sans_thai/`); the monospace slot uses Roboto Mono. Decouples font asset management from `ImGuiLayer` and gives panels a single, type-safe entry point for picking fonts.

- **2026-05-09 — Removed the ImGuizmo gizmo integration entirely.** State-corruption symptoms (handles staying active after release / phantom click latching) survived the NFD→ImGuiFileDialog swap and a four-step integration audit (move imguizmo link off the engine DLL boundary, move `BeginFrame()` inside the dockspace `Begin`, pass an explicit `ImGui::GetWindowDrawList()` to `SetDrawlist`, and add `SetGizmoSizeClipSpace(0.1f)` + `AllowAxisFlip(false)`). Decision: rip out all gizmo code (`viewport_panel::RenderGizmos`, `EditorLayer::HandleGizmoTypeChange`, the gizmo-deselect guard in `OnMouseButtonPressed`, `EditorContext::GizmoType/GizmoMode`, `TransformEditCommand`, the toolbar's gizmo combo + World/Local toggle, the `imguizmo` link in `engine/CMakeLists.txt` + `weaver/CMakeLists.txt` + the block in `vendors.cmake`) and start fresh in a future commit. **The visual transform gizmo is disabled.** Translation/rotation/scale can still be edited via the inspector input fields (those route through `PropertyEditCommand<T>` and undo correctly). The `vendor/imguizmo` submodule remains on disk but unreferenced — to be removed in a follow-up commit via `git submodule deinit -f vendor/imguizmo` + `git rm -f vendor/imguizmo`.

- **2026-05-08 — Dropped NFD (nativefiledialog-extended) in favor of ImGuiFileDialog.** Multiple sessions of trying to fix an `ImGuizmo` state-corruption bug caused by NFD stealing OS focus and blocking the main thread (symptoms: phantom mouse-down latched after dialog closed, gizmo handles becoming unresponsive). Workarounds attempted and discarded: `glfwFocusWindow` post-call, `ImGui::GetIO().ClearInputMouse()`, modified `ImGuiLayer::BlockEvents` ordering. Root cause is fundamental: NFD blocks the GLFW main thread and the OS dialog sits on top of the editor as a separate native window, so input events are dropped without ImGui ever seeing the press/release pair. Fix: replaced NFD with `ImGuiFileDialog` (vendor/imguifiledialog) — fully in-process ImGui modal, no thread blocking, no focus loss. The async API is wrapped by `Weaver::FileDialog` (`weaver/src/editor/file_dialog.{h,cpp}`): `Open / Save / PickFolder` register a callback, `Render()` polled once per frame from `EditorLayer::OnImGuiRender` dispatches the callback when the user clicks OK. Inspector callbacks capture entity by `UUID + scene shared_ptr` (not raw entity handle) so a scene swap mid-dialog is safe. `SceneManager::SaveScene/SaveSceneAs` gained an optional `on_complete` callback so the "Save Changes?" modal's pending action only fires after an async save resolves.

## Phase 7 — Post-Processing & Rendering Polish

*Deferred from the IBL slices: 2D and 3D currently tonemap independently inside their own shaders, so a mixed scene shows them at inconsistent brightness.*

- [x] **Unified HDR pipeline** *(2026-05-24)* — RGBA16F scene framebuffer; `tonemap.vert/.frag` fullscreen-triangle pass applies ACES + sRGB once at the end. Removes per-shader tonemap from `mesh.frag`. 2D linearization is the follow-up.
- [x] **Bloom** *(2026-05-24)* — Jimenez 2014 dual-filter (downsample/upsample with additive blending); 6-mip chain, 13-tap downsample with folded bright-pass, 3x3 tent upsample. Composited inside `tonemap.frag` pre-ACES. Scene-level UI/serialization for threshold + intensity pending.
- [x] **Anti-aliasing** *(2026-05-24)* — FXAA Console variant (compact NVIDIA-derived); runs post-tonemap on the LDR sRGB buffer. Chain: HDR scene → tonemap → LDR intermediate → FXAA → final display. Fixes aliasing on bright PBR highlights and contrasty silhouettes.
- [ ] *(stretch)* vignette, color-grading LUT, exposure control.
